# DD-100 · 加密项目尽职调查引擎

**100 个维度，证据门控打分，红旗不会被平均掉。**

DD-100 把加密项目的尽调（交易所上币评审、投资筛选、研究报告）做成一条可复现、可审计的流水线：Claude Skill 负责研究和带引用的判断，确定性的 harness 负责核验每一条判断的证据、计算分数、执行红旗闸门、输出给决策委员会的备忘录。

## 它解决什么问题

大部分糟糕的上币决策不是因为信息不够，而是五种老毛病：

1. **致命缺陷被平均掉**：团队强、叙事热，盖过了一个能无限增发的私钥。→ 16 个红旗闸门在打分之后执行，critical 直接拒绝，major 封顶 C 级。
2. **项目方自报的数据直接进了备忘录**。→ 项目方的说法单独存为 claims，和独立来源交叉核对，矛盾会被计数、可触发闸门。
3. **"73.4 分"掩盖了多少是猜的**。→ 每个结果都带证据覆盖率和分数区间。
4. **两个分析师两套标准**。→ 同一框架、固定锚点、按赛道配置权重。
5. **AI 写得很流畅但无从溯源**。→ 没有引用就不计分；引用不存在的证据直接拒绝；单一自报来源的"高置信"自动降级；必须人工完成的项（KYC、做市协议、法律意见书）agent 不能填。

## 框架

10 大支柱 × 10 个维度，每项 0–4 分：团队治理、产品技术、安全合约、代币经济、链上数据、市场结构、商业模式、竞争壁垒、社区分发、法律合规。其中 37 项由规则从指标自动计算，60 项由 agent/分析师按锚点判断并必须引用证据，3 项只能人工完成。完整清单见 [docs/FRAMEWORK.md](docs/FRAMEWORK.md)。

## 快速开始

```bash
pip install -e ".[dev]"
dd100 validate
dd100 run examples/halcyon/manifest.yaml     # 有条件通过，B 级
dd100 run examples/moonvault/manifest.yaml   # 拒绝，触发 RF01
dd100 run examples/hyperliquid/manifest.yaml # 真实项目：有条件通过，B 级
pytest -q
```

仓库里有三个示例。

[Hyperliquid（HYPE）](examples/hyperliquid) 是真实项目。币安 2026 年 9 月 24 日上了它的现货，带种子标签。我们只用 61 个公开来源，按框架跑了一遍尽调，结论是"有条件通过"，B 级，66 分（区间 41–81），和币安"带种子标签上币"的处理基本吻合。

这个项目业务很强：年化手续费约 9 亿美元，没有任何激励补贴，收入全部归持币人（主要通过链上回购）。短板在控制权、安全审计和牌照：基金会验证人掌握约 49% 的质押，L1 不开源也没有公开审计，英国 FCA 还发过警示。

整个过程里还有一处被纠正：第一次跑的时候，一条重大红旗是根据被误读的来源触发的。独立核查后回到合约代码本身，证明那条说法不成立，结论也跟着改了。这正好说明核验层在起作用。

另外两个示例 Halcyon 和 Moonvault 是虚构项目，数据是编的，专门用来把每条流程都跑到。
